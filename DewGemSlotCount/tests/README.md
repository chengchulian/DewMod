# 精华槽回归检查

使用 .NET Framework 4.8.1 与 MSBuild 编译 `RegressionHarness.csproj`，然后运行 `bin/Release/DewGemSlotCount.RegressionTests.exe`。构建和运行时均需设置 `ShapeOfDreamsHome`。

测试以 x64 编译生产槽数控制器、customData 单向同步、技能补丁、补丁生命周期与结算补丁，检查四槽写入、重复初始化、运行时配置修改、混沌重算、八槽上限、位移槽保留、服务端权限、房间重建和混沌读档初始化顺序。Unity 与游戏对象使用桩实现，网络检查验证原生四槽字段和完整槽数快照，不模拟实际传输。

重载检查直接执行生产技能补丁的空实例路径，验证卸载空窗中的初始化、读取、写入与合并入口；连续五次撤回和重施配置，检查基础槽与位移槽不累计且奖励槽保留。每次清空程序集状态后，从原生字典接管重载前的奖励槽；客机始终直接读取房主快照，不发送握手或确认消息。真实 Harmony 检查覆盖旧随机身份和当前稳定身份补丁的清理、重复清理，以及同一入口上其他 Mod 补丁的保留。

混装检查复现房主四槽改八槽：同一客机只读取更新后的 customData 即升至八槽，原生字段始终最多四槽。覆盖混沌六槽、晚加入、客机重载、快照缓存失效、非法快照回退与切房间。结算使用游戏已有字典携带完整槽数，原生列表保持四槽；检查正常和异常绘制后兼容值均恢复。还通过真实 Harmony 注册和调用生产结算补丁，回归辅助方法误用 `Prepare` 名称导致启动失败的问题。

位移编辑检查直接编译生产 `MovementEditLayout`，验证历史容器上移 350、横坐标与深度保留、可见性与交互、重复调用不累加、不重启动画、切换模式、关闭优化和退出编辑时恢复原位。动画桩立即应用目标位置，不模拟 Unity 的逐帧插值。几何检查使用 `GameSource/asset/ExportedProject/Assets/Scenes/PlayGame.unity` 中位移四槽的非对称端点，以及 Gem Group 的轴心、偏移和 0.9–1.3 缩放数据，验证生产计算在展开过程中上下镜像距离一致。

另外读取已安装游戏程序集的 IL，核对技能初始化、混沌重算、结算刷新入口，以及两个手柄导航方法中被替换的身份技能边界常量。

游戏内验收：

1. 房主将 Q 设为 8 槽，已装 Mod 与未装 Mod 的两台客机同时加入，分别显示并使用八槽和四槽。将基础槽改为 3、混沌上限设为 8，重复加槽，确认双方上限分别为八槽和四槽。重新生成英雄、重连及再次建房后复查。
2. 双方安装 Mod，分别检查 5、6、7、8 槽在 HUD、TAB 与结算中的上/下排数量：2/3、3/3、3/4、4/4；检查最后一槽的精华图标与提示框。
3. 切换结算玩家，确认每个精华的归属及提示框跟随玩家更新。切换本地优化选项，确认原有四槽布局保持一致。
4. 开启位移技能编辑或为位移配置槽数，使用键鼠和手柄打开编辑，检查位移保留历史横向位置与缩放，仅原容器上移 350，位移可选、关闭后恢复原位。反复开关、切换输入模式及开关优化，确认位置无累计偏移。
5. 位移为零槽且只开启位移堕落混沌加槽时，选择加槽奖励，确认位移显示并可取得第一个槽。
6. 重复混沌加槽、修改基础槽和加载存档，确认槽数不重复叠加且总数至多 8。
7. 位移设为四槽，确认左右端点同高、弧线对称。QWER、身份和位移分别配置 5–8 槽，观察展开动画前、中、后及收起过程，确认上排与对应官方下排到技能中心的距离一致，精华图标与提示框仍正常。
8. 在已有英雄和已打开的 HUD / TAB / 结算界面重载 Mod，检查八槽重新显示、位移仍沿历史位置上移且不累计。保持已装 Mod 的客机连接，房主重载后确认客机重新获得八槽，并继续接收配置修改；随后只重载客机再次复查。

联机传输、实际 UI 位置和输入交互需在游戏中验证。
